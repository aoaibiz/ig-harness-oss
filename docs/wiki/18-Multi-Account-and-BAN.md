# 18. Instagram API のレート制限と遵守

IG Harness から Instagram API を利用する際の、送信上限とプラットフォームポリシーを守るための運用ガイドです。

> ファイル名は既存の Wiki リンクとの互換性のため維持しています。本文は Instagram 向けです。

---

## 基本方針

- Meta の最新の利用規約、開発者ポリシー、Instagram Messaging API の仕様に従う。
- 受信者が予期していないメッセージや、同じ内容の反復送信を行わない。
- 受信者の拒否や配信停止の意思を尊重し、以後の送信対象から除外する。
- API エラー時に送信経路を切り替えて処理を継続しない。
- API の制限やエラーが発生した場合は送信を停止し、メッセージ内容を加工して継続しない。

API の上限や利用条件は変更される可能性があります。固定の数値を前提にせず、運用時点の公式ドキュメントと API レスポンスを確認してください。

---

## 送信レートの管理

送信処理は一元化したキューを通し、次のルールで流量を制御します。

1. 運用時点の公式上限を超えない値を設定する。
2. 短時間の集中送信を避け、許容範囲内で送信時刻を平準化する。
3. `429 Too Many Requests` を受けたら新規送信を停止し、レスポンスで待機時間が示された場合はそれに従う。
4. 待機時間が示されない一時エラーは、回数を制限した指数バックオフで再試行する。
5. キューが設定した上限を超えた場合は、送信を遅延または中止し、別経路へ自動転送しない。

レート設定を変更する場合は、変更理由、参照した公式仕様、変更日時を運用記録に残します。

---

## エラー時の扱い

| 状態 | 対応 |
|---|---|
| `429` | 送信を停止し、指定された待機時間の経過後に再開する |
| `401` / `403` | 再試行を繰り返さず、認証情報・権限・ポリシー適合性を確認する |
| その他の `4xx` | リクエスト内容を修正するまで再送しない |
| `5xx` / 一時的な通信失敗 | 上限回数を設けた指数バックオフで再試行する |

認証や権限のエラーが継続する場合は対象の送信を停止し、Meta 側の設定と公式ドキュメントを確認してください。

---

## 監視項目

運用時は少なくとも次を記録し、異常を検知できるようにします。

- API リクエスト数と成功率
- HTTP ステータス別のエラー数
- `429` の発生数と待機時間
- 再試行回数と最終的な失敗数
- キュー滞留数と送信待ち時間
- 配信停止要求の処理結果

アクセストークン、個人情報、メッセージ本文はログへ記録しません。エラー率の上昇やキューの長時間滞留を検知した場合は、自動送信を停止して原因を確認します。
